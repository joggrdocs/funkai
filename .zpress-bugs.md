# zpress Bug Reports

## Bug 1: `@zpress/ui@0.8.3` — Missing `FileTree.css` causes build failure

### Versions

- `@zpress/kit`: 0.2.8
- `@zpress/ui`: 0.8.3 (transitive via kit)
- `@zpress/cli`: 0.4.3
- `@zpress/config`: 0.4.0
- `@zpress/core`: 0.7.3

### Description

`zpress build` fails because the generated `.rspress/runtime/virtual-global-styles.js` imports a CSS file that does not exist in the published `@zpress/ui@0.8.3` package.

### Steps to Reproduce

1. Install `@zpress/kit@0.2.8`
2. Have a valid `zpress.config.ts` (passes `zpress sync` and config validation)
3. Run `pnpm zpress build --clean --no-check`

### Error Output

```
error   build failed in 5.75 s (node_md)
error   build failed in 5.76 s (node)
error   Build errors:
File: ./.rspress/runtime/virtual-global-styles.js:1:1-251
  × Module not found: Can't resolve '.../@zpress/ui/dist/components/FileTree/FileTree.css'
    in '.../.rspress/runtime'
   ╭─[1:0]
 1 │ import ".../@zpress/ui/dist/components/FileTree/FileTree.css";
   · ──────────────────────────────────────────────────────────────
 2 │ import ".../katex/dist/katex.min.css";
   ╰────
error   build failed in 7.67 s (web)
```

### Analysis

- The file `dist/components/FileTree/FileTree.css` does not exist in the published `@zpress/ui@0.8.3` npm package.
- Verified by running `npm pack @zpress/ui@0.8.3 --dry-run` — no `FileTree` files appear in the package contents.
- The import is generated by `@zpress/core` in `virtual-global-styles.js`, so this is not a stale build artifact — it reproduces after `zpress clean` and fresh `zpress build --clean`.
- `zpress sync` and config validation both pass — only the Rspack build step fails.
- This was introduced in the `0.8.2 → 0.8.3` bump (kit `0.2.7 → 0.2.8`).

## Bug 2: `zpress diff` uses `git status` — unusable as Vercel `ignoreCommand`

### Versions

- `@zpress/cli`: 0.4.3

### Description

`zpress diff` uses `git status --short` internally, which only detects uncommitted/unstaged changes in the working tree. This makes it unsuitable for use as a Vercel `ignoreCommand`, because Vercel checks out a clean working tree at the exact commit SHA — `git status` will always return empty, so `zpress diff` always exits 0 (skip build).

### Steps to Reproduce

1. Set `vercel.json` → `"ignoreCommand": "pnpm zpress diff"`
2. Push a commit that changes files in zpress source directories
3. Vercel skips the deployment every time (shows "Ignored")

### Relevant Source (from `@zpress/cli@0.4.3` dist bundle)

```js
function gitChangedFiles(params) {
    const [err, output] = execSilent({
        file: 'git',
        args: [
            'git',
            'status',
            '--short',
            '--',
            ...params.dirs
        ],
        cwd: params.repoRoot
    });
    // ...
}
```

### Expected Behavior

`zpress diff` should support comparing against a ref (e.g., `HEAD^`, `main`, or a specific SHA) so it can detect changes between commits, not just uncommitted changes. For example:

```bash
# For Vercel ignoreCommand (compare current commit vs parent)
zpress diff --ref HEAD^

# For PR context (compare against base branch)
zpress diff --ref main
```

This would use `git diff --quiet <ref> HEAD -- <dirs>` instead of `git status --short -- <dirs>`.

### Workaround

Use a manual `git diff` in `vercel.json` with all source directories listed explicitly:

```json
{
  "ignoreCommand": "git diff HEAD^ HEAD --quiet vercel.json zpress.config.ts docs/ packages/agents/docs/ packages/models/docs/ packages/prompts/docs/ packages/cli/README.md examples/ contributing/"
}
```

This is fragile because it requires manually maintaining the path list whenever `zpress.config.ts` sections change.
